# JoeOS Repository Audit

Date: 2026-07-29

Status: complete, read-only baseline audit

Scope: every repository-owned file outside dependency and Git object directories

## Executive result

JoeOS already has a useful local vertical slice. FastAPI serves a polished single-file PWA, samples the VPS every five seconds, persists telemetry and profile state in SQLite, and proxies read-only chat to Lemonade. The SwiftUI wrappers load that private web application. These behaviors are compatibility requirements and must not regress.

The current code is not yet the requested enterprise operating system. The local server is one 977-line module; the local web UI is one 4,231-line document; the Sites application is an iframe around a separate simulated dashboard. There is no identity boundary, widget registry, orchestration engine, durable memory, search/RAG, automation runner, approval protocol, WebSocket stream, PostgreSQL/Redis/pgvector layer, or synchronized offline cache.

## Current dependency graph

```text
iPhone PWA / macOS WebView / browser
  -> same-origin FastAPI routes
     -> SQLite WAL
        - system_metrics
        - bots (profiles, not executing agents)
        - events
     -> psutil (CPU, RAM, disk, uptime, temperature)
     -> Lemonade loopback API
        - health and model discovery
        - GPU/runtime telemetry
        - non-streaming chat completion

Cloudflare Sites request
  -> Vinext worker
     -> Next App Router
        -> full-screen iframe
           -> command-center.html
              -> React 18 and Font Awesome CDNs
              -> in-memory simulations only

Dormant paths
  - Sites identity-header helper (not imported)
  - Drizzle/D1 factory (D1 binding disabled; schema empty)
  - retired Supabase migration
  - unreachable legacy Render/GitHub setup code
```

## Working compatibility baseline

- Same-origin `/api/metrics`, `/api/bots`, `/api/events`, `/api/status`, and `/api/chat` routes.
- Five-second VPS telemetry collection and bounded SQLite retention.
- Lemonade health/model discovery and private inference proxy.
- Bot-profile create, start, and stop persistence with audit records.
- Responsive glass command center, mobile drawer, filters, modals, notification panel, log export, and assistant.
- Tailscale-aware Linux/macOS/Windows launchers.
- PWA manifest and basic service worker.
- Basic CSP and response security headers.
- macOS and iOS WKWebView shells.
- Root tests: eight backend and five frontend checks pass.
- Sites tests: two canonical generated-artifact tests pass.

### Generated Sites output

Every file under `joeos-web/dist` was inspected by type, size, hash relationship, and manifest/config content. Client static assets match their public sources; server, SSR, RSC, runtime, error-boundary, and manifest files are generated Vinext output. The generated hosting metadata is stale relative to the tracked project metadata. Generated Vinext metadata includes a prerender secret, so `dist` must remain ignored and must never become source. No D1, R2, Vectorize, queue, service, or application-secret binding is configured.

### Repository topology

The workspace root is not a Git repository. `joeos-web` is a nested Git repository with one local commit (`f29bfcb`), no remote, and six untracked duplicate files. A root-level `git add` would risk recording `joeos-web` as an unintended embedded repository. History must be preserved and deliberately unified before internal root commits begin.

## Security findings

1. Any client that can reach the VPS service can currently read telemetry, create or mutate profiles, and consume inference; there is no application identity or authorization.
2. Credentials previously pasted into conversation were not found in repository files, but all live-looking restricted credentials must be rotated independently of code changes.
3. Browser access is HTTP. Tailscale protects transport within the tailnet, but an HTTPS origin is still required for the full iPhone/PWA secure-context feature set.
4. SQLite permissions are restrictive but its contents are not encrypted.
5. Inline/CDN assets weaken CSP, offline reliability, and supply-chain control.
6. The future runner must not inherit browser authority. Shell, Git, download, deploy, secret, and external-communication actions require signed, expiring approvals, policy checks, idempotency, and audit records.
7. Multiple Uvicorn workers would duplicate the current collector.
8. `/api/status` causes four Lemonade calls per request and needs caching/rate protection.
9. Current global permissions policy disables the future voice, camera, and geolocation capabilities.

## Build and environment findings

- Root Python, shell, JSON, plist, and JavaScript syntax checks pass.
- Root in-process route smoke tests pass; Lemonade-offline chat fails safely with HTTP 503.
- A fresh `joeos-web` build cannot be judged on this host because Node 20.20.2 is installed while Vinext requires Node 22.13+. Existing generated-output tests pass.
- No credential values or secret-shaped tokens were found in repository-owned files.

## Baseline decision

The root local application remains the operational compatibility shell. The Sites dashboard remains a visual/reference fixture until it is connected through authenticated APIs. Enterprise functionality will be introduced behind versioned contracts, then UI modules will migrate incrementally. No simulated operation may be relabeled as real.
