# Workspace updates

The existing dashboard now has a shared Updates drawer and a compact notification bell on phones. New offscreen Codex messages, genuine runner permission requests, and observed errors/blockers/review notices create right-side cards. Routine task changes and successful tool milestones are retained in history without a popup; messages already visible in the current chat do not create a popup. Cards fade after eight seconds; hover or keyboard focus pauses dismissal. Clicking opens a full detail view. Only three cards display at once (one on narrow phones); all observed items enter history. No synthetic activity is emitted to make an idle system look busy.

History retains the latest 500 observed events per signed-in identity/access key in this browser, encrypted with AES-GCM using a key derived from the access key. No credential or plaintext message is written by this feature. The drawer warns when persistence is unavailable. Reload restores history; sign-out, access changes, and invalid authorization discard visible/in-memory history and abort requests. Another account does not inherit private agent messages. Server notifications and activity can be recovered from their existing API windows (120 notifications, 200 activity rows); this is not an unlimited or cross-device archive. Rotating credentials makes the old encrypted device history inaccessible. Browser storage deletion also removes this local copy.

The popup preference is saved on this device. Existing in-app notification preferences, quiet hours, agent-popup preferences, and reduced-motion settings are respected. Muting popups does not remove history. Mark all read changes the device history only; the original Settings notification center retains its server read controls. Permission details link to the authoritative current request; viewing, dismissing, or marking a notice read never approves, denies, resumes, publishes, or merges anything.

## Update cadence and limits

- Tasks, projects, activity, bridge runs, notifications and intelligence refresh on initial load, explicit refresh, supported data mutations, return to the visible tab, and navigation when the previous snapshot is over 15 seconds old. A successful read does not schedule another scan. Failures back off and retain the last known data. The drawer states when the data was checked.
- Selected active Codex runs poll recorded events about every two seconds in chat and five seconds elsewhere; full event pages catch up at 750 ms. Known background active work windows poll approximately every three seconds. Completed runs do not continue polling. These are reads, not model generations.
- The native permission inbox reuses the workspace catalog. The catalog refreshes about every 15 seconds for the selected active run and every 60 seconds otherwise while visible; explicit refresh is immediate. The one-second permission countdown renders local time without an HTTP read.
- Models, agent configuration, settings, collaborators and memory refresh as part of an actual dashboard snapshot only when their cache is older than 30 seconds. Health refreshes once a minute while Home, Agents or Settings is visible. Model-choice metadata has a separate ten-minute backend cache and does not hold the run/permission lock during its RPC.
- Browser waiting messages still need a visible tab to dispatch; relevant task-dependency reads continue while work is waiting. Accepted execution remains on the server. Browser timers and HTTP reads do not themselves consume model-generation credits. A scheduled Codex automation does; the thread's incoming-project monitoring automation remains paused.
- Data and history keep updating during editing, but visual redraws wait until forms, dragging, move sheets, or the history drawer are finished. Selectors retain the current chat/terminal context. Data redraws occur only when snapshots change.

This is bounded near-real-time polling, not a server-push transport. True push delivery and complete cross-device event replay require a backend event stream and durable retention protocol. This cadence change adds no worker, execution authorization, or ownership changes. Backend history/model support is covered separately in MOBILE_WORKFLOW_AUDIT.md.
