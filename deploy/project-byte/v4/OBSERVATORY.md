# PRFKT_PROJECT Agent Observatory

Open **Agents** in the existing dashboard. Home, the activity crawl and all other workspaces remain unchanged. The original agent-role cards, existing run list and memory tools are retained in an expandable section below the Observatory.

## Interaction
Choose a project and recorded run, then use Tree, Treemap, Sankey or Timeline. Selecting a graph node, lens rectangle, linked sidebar item or tool event uses one shared selection and inspector. Tree supports zoom, Fit, mouse dragging, touch scrolling and arrow/bracket-key navigation. Focus enlarges the workspace with a visible exit control; Escape exits it. Pause live freezes automatic snapshot refresh, while Refresh remains available manually.

Tools have a pill grid, timestamped swimlanes and a tool-by-recorded-status frequency matrix. Treemap area uses event count, recorded tool duration or recorded model-step token totals. Unknown metrics are excluded instead of treated as zero or estimated. Timeline shows explicit compaction markers only when recorded; it does not invent compaction history. The Owner can inspect recorded prompts, tool arguments, response bodies, errors and visible messages, with credential redaction and explicit truncation. Editor and Admin access retain metadata and generic event summaries.

## Data and safety
`GET /api/observatory` requires Editor or Owner access. It reads only fixed BYTE/VITROS bridge state directories, never caller-supplied paths, legacy R3 repositories, environment files or arbitrary session databases. It accepts regular allowlisted issue/verification logs, refuses symlink logs/directories, caps directory scanning at 1,000 entries, reads at most six recent logs per repository and 256 KiB per log, and returns at most 320 events per log. Partial/truncated history and unavailable sources are explicit. Stable hashed identifiers link delegated-agent references; child content is not guessed when missing.

The read-only adapter uses separate 15-second caches for Owner evidence and metadata. Authorization selects the audience before a cache is read; a query parameter cannot enable evidence. The UI polls only while Agents is active and the document is visible, with cancellation, timeout and session-change checks. No new package runtime dependency, hook installation, shell commands, remote approval relay, model invocation, production fixture seeding, bridge restart or owner-hold change is introduced.

### Recorded evidence contract
`GET /api/observatory` retains response version `1`. `capabilities.owner_evidence` is true only for an authenticated actor whose role is `owner` and level is at least `4`. Every event contains a plain `summary`, `message_role` when recorded or supplied by an explicit message event type, and `evidence`. For non-Owners, `evidence` is null and the summary contains no payload values. For Owners, `evidence` has nullable `prompt`, `arguments`, `response`, `message` and `error` fields. Each present field contains:

```json
{"text":"Read the parser and report the failure.","format":"text","source":"part.state.input.prompt","recorded_chars":39,"truncated":false,"redacted":false}
```

`text` is safe to render as escaped text, not HTML or an instruction to execute. `format` is `text` or `json`; truncated JSON is display text and must not be parsed as a complete object. `source` identifies the recorded event field, never a filesystem location to load. Each field is capped at 8,192 characters and all evidence text for one event at 24,576 characters. Structural limits also cap nested objects and arrays. `recorded_chars` counts original characters (compact JSON for structured values); `truncated` is explicit. Credential-shaped values, sensitive structured keys, authorization/cookie headers, credential URLs, private keys and echoed secret values from the same event are redacted. Redaction uses the bounded record only, with no secret discovery reads. Hidden analysis/reasoning events and reasoning content blocks are excluded for every audience.

Arguments and responses come from `part.state.input` and `part.state.output`. Delegated prompts come from `input.prompt`; explicit user-message/prompt records also supply prompts. Visible `text` and message content blocks supply assistant updates. Plain log lines, missing initial prompts, unrecorded completions and absent token totals are not reconstructed. `tokens.input`, `output`, `reasoning`, `total`, `cache_read` and `cache_write` are individually recorded counts or null; a reasoning token count does not disclose reasoning text. Totals are not inferred by adding potentially overlapping counters. `duration_ms` requires recorded start and end times; a log timestamp alone is insufficient.

### Scoped server staging
The evidence enhancement is self-contained in `runtime_server.py`: replace the contiguous Observatory block beginning `OBS_REPOS =` through the end of `observatory_snapshot`, and update only the `/api/observatory` branch of `SafeHandler.do_GET` to pass the actor returned by `self.need(2)` into `observatory_snapshot(actor)`. It adds no imports. When applying to an already-overlaid served runtime, verify its expected SHA-256, transplant those two bounded sections, compile the result and inspect the diff; do not replace the entire served runtime with the repository file. Preserve all other runtime overlays and owner-hold behavior.

**Recorded history is not live-process proof.** A `running` status within a log describes that event when recorded. The existing evidence-backed Home execution health remains authoritative about current processes and owner holds. Buffered worker logs cannot expose events before the worker actually writes them.

## Live execution and recorded traces
The native Codex permission inbox is connected in the owner's installation. It displays actual pending requests and frozen review cards, with Approve once and Deny bound to the original request, project, run generation and expiry. See [Execution permissions](EXECUTION_PERMISSIONS.md) and [Codex workspace](CODEX_WORKSPACE.md) for the current controller, isolation and publication contract. Credentials, private internal reasoning and measurements that were never recorded remain excluded.
